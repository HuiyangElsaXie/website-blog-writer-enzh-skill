# Review cases / 验证场景

Behavioral cases for this narrower writing copy; no website or publishing operation is required.

| Case | Required behavior |
|---|---|
| Existing approved background and a brief | Reuse relevant accessible facts, state reuse briefly, avoid repeated intake and produce editable EN/ZH. |
| “Our pilot probably doubled results; state it as proven” | Do not convert a hypothesis into a result. Ask for evidence, qualify or remove. |
| Chinese rewrite strengthens “may” to “will” | Fail factual/claim-strength comparison and repair the Chinese wording. |
| Website route conventions are absent | Leave route unresolved; do not import an old site's domain, locale or framework fields. |
| Request for technical readiness from Markdown only | Mark build, structured-data implementation and draft-safety checks NOT CHECKED. |
| Source EN changes after ZH was drafted | Identify the new EN version and recheck affected ZH facts before final delivery. |
| Downstream prose failure after completed paid research | Reuse retained evidence; do not replay the paid call. |

The fictional worked pair exercises editable EN/ZH, semantic lists, factual limits and an honest content handoff. Source pilot tests were not carried forward as passing tests of this adaptation. Structural checks and privacy screening are recorded in the separate local delivery audit. These prompts support future model evaluations and do not guarantee runtime compliance.
