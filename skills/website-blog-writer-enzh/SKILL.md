# Website Blog Writer EN/ZH

Optional first-use reference: [the existing paired EN/ZH guide and review handoff](../../examples/fictional-guide.md). It is a fictional writing example, not measured evidence; do not require it for every edit. Keep the full repository and provide this nested entrypoint explicitly so ../../examples and root provenance/rights remain available. Copying only the child skill folder omits those resources.

Produce useful bilingual articles grounded in the user's permitted evidence. End with editable candidates and one consolidated review package. The current assistant writes the prose; no external writer or publishing adapter is required.

## Establish the writing contract

Identify whether the task is topic planning, drafting, revision, bilingual adaptation or review. Reuse relevant user-provided or authorized accessible background before asking questions. Briefly state which background informed the work and what was unavailable; never claim to read an inaccessible file. Do not export private source text or unrelated personal context.

Capture only what changes the work: business/product or subject facts, audience, purpose, language/locale, topic, evidence and disclosure limits, positioning, voice, exclusions, length and deliverable format. Ask only for a material factual, directional or disclosure decision. Proceed with adequate information; mark minor gaps rather than inventing them. A user's writing request can authorize the writing; no inherited private queue or infrastructure approval is required.

Use an explicitly requested output location or an ordinary task-local location. Do not infer private paths. Resume from readable completed artifacts and revise only affected parts.

## Workflow and evidence

Read [references/editorial-workflow.md](references/editorial-workflow.md) for brief, claims, English, Chinese, candidate integrity and bounded repair. Read [references/content-handoff.md](references/content-handoff.md) when a website handoff is requested.

1. Establish the purpose, evidence plan and concise brief; check recent content for duplication only when accessible.
2. Draft English and review brief fit, claims, privacy and whole-piece naturalness.
3. Identify the exact English candidate used for Chinese adaptation; preserve its version/hash when files are used.
4. Write native Simplified Chinese. Compare facts, claim strength, examples, attribution, numbers, links and exclusions against that English candidate.
5. Repair material findings within the bounded review process, then deliver both candidates and one concise review package.

Do not force every request through all stages: an English-only edit or a review of provided drafts stays within that scope. If the provided English source contains a material unsupported claim, resolve or flag it before adapting it into Chinese.

## Deliverable and stop point

Use editable Markdown/text by default, or the user-requested editable format. Provide:

- final EN and ZH candidates, or the requested subset;
- brief background-reuse statement, key sources, disclosure limits and material gaps;
- a claim/evidence summary and EN/ZH factual review result;
- concise audit/repair notes and exact candidate identity;
- a semantic website handoff only when useful or requested;
- status `READY FOR REVIEW` or `DRAFT — BLOCKED` with the precise blocker.

Keep notes outside article body. A candidate lock records integrity, not user approval. Review, approval and publication are separate states. Changes after candidate identification require affected bilingual/claim checks again.

Stop at the requested writing/review boundary. This skill does not read credentials, log into services, operate accounts, run paid discovery automatically, modify website files, create commits, push, deploy, schedule or publish. A separate authorized workflow must handle any later external action.
